# カテログ

食品マスター・日々の食事・体重を端末内に記録する、日本語のオフライン対応PWA（ホーム画面に追加して使うWebアプリ）です。減量にも増量にも使えます。ユーザー登録、外部データベース、クラウドAPIは使いません。データはすべて端末のブラウザー内に保存されます。

## 主な機能

画面の上のタブで「記録」「履歴」「食品」「データ」を切り替えます。

- **記録**：見出し（例：「2026/11/14(土)の記録」。今日なら後ろに「今日」）を押すと、記録する日を選べます。
  - 食品は「食品を選択」から一覧を開き、検索欄に食品名を入れると絞り込めます（空欄なら全件）。各食品の「栄養成分」で、基準量あたりのカロリーとPFCを確かめられます。
  - 「個数で記録」の食品は個数（小数可）、「重さで記録」の食品は重さ（g）を入れます。記録した数量はカードの「数量」の欄でそのまま直せ、合計にすぐ反映されます。
  - カードの「⋯」から削除できます（手入力の記録は編集も）。
  - カロリー・タンパク質・脂質・炭水化物の合計とPFCバランスを表示します。
  - 体重は0.1kg単位で記録します。
- **手入力で追加**：食品マスターに登録せず、その日の食事記録だけに追加できます（成分表から探すこともできます）。
- **ほかの日の食事をコピー**：コピー先の日付を開いた状態で実行します。コピー元の日付を選び、「既存の記録に追加」または「既存の記録を置き換え（確認あり）」を選びます。
- **食品**：食品の登録・編集（カードを押す）・削除（編集の画面から）・検索・並べ替え（1つの「並び替え」で、名前順・タンパク質／脂質／炭水化物が多い順・少ない順。栄養素の順はカロリーあたりの量で並べ、各カードに「100kcalあたり ○g」を表示）。同じ名前の食品も別に登録できます。「重さで記録」の食品は100gあたりの値で登録し、単位はgで固定です。
- **成分表から探す**：食品の登録・手入力のときに、日本食品標準成分表から食品を探して100gあたりの値を入れられます（下の「成分表の出典」参照）。
- **履歴**：
  - 「体重の推移」：目標体重と達成目標日（なくても可）を設定できます。グラフの期間は「いつから」「いつまで」で、体重を記録した日から選びます（「いつまで」は達成目標日も選べます）。初めは最初と最後の体重の記録の日までで、期間内の記録を実際の日付の間隔で表示し、記録のない日は補完しません。点を押すとその日の体重を表示します。グラフの上に「最新」「先週比」「目標まで」を表示し、目標の線は表示・非表示を切り替えられます。
  - 「記録一覧」：食事・体重のどちらかを記録した日だけを、年月のボタンで切り替えて表示します。日付を押すとその日の記録を開きます。1日分（「⋯」から）・選んでいる年月の分・すべての記録を、確認のあとに削除できます。
- **データ**：全データのJSONバックアップと復元、記録一覧のCSV出力（1日ごとの合計と食事の明細）ができます。

## 使用技術

- HTML / CSS / JavaScript のみ。フレームワーク、ビルド工程、外部ライブラリ、外部通信はありません。
- 保存：ブラウザーのIndexedDB
- オフライン：Service Worker（`sw.js`）によるキャッシュ
- 開発用サーバー：Python 3（標準ライブラリのみ。`start_server.py`）
- iOSネイティブ化の準備：Capacitor 8（`@capacitor/core`、`@capacitor/ios`、`@capacitor/cli`）。追加のCapacitorプラグインは使っていません。

## 成分表の出典

「成分表から探す」の食品データは、日本食品標準成分表(八訂)増補2023年から引用しています。

- 出典：日本食品標準成分表(八訂)増補2023年（文部科学省）
  https://www.mext.go.jp/a_menu/syokuhinseibun/index.htm
- `tools/20260327-mxt_kagsei-mext-000029402_02.xlsx` は、文部科学省が公開している成分表の Excel ファイルそのものです（手を加えていません）。
- `seibun.json` は、`tools/convert_seibun.py`（Python 3、標準ライブラリのみ）でこの Excel から作ります。読み・言い換え・分かりやすい表示名は `tools/` の辞書（`seibun_readings.json`・`seibun_aliases.json`・`seibun_labels.json`）で付け加えています。

  ```powershell
  python tools/convert_seibun.py
  ```

## データ保存の仕組み

### 保存場所

データはIndexedDB（データベース名 `genryo-note`）に保存され、次の4つの領域に分かれています。

アプリの表示名は「カテログ」（旧名「減量ノート」）ですが、中の識別名は `genryo-note` のまま変えていません（IndexedDB のデータベース名、Service Worker のキャッシュ名 `genryo-note-vNN`、バックアップの `app: "genryo-note"`、バックアップ・CSV のファイル名、iOS のアプリID）。変えると、今までの端末のデータや前に作ったバックアップが読めなくなるためです。

| 領域 | 内容 | キー |
| --- | --- | --- |
| `foods` | 食品マスター（名前、種類、基準量、単位、基準量あたりの栄養値） | `id` |
| `meals` | 食事記録（日付、数量、食品名、単位、単位あたりの栄養値、計算済みの栄養値） | `id` |
| `weights` | 体重記録（1日1件） | `date` |
| `settings` | 目標体重・達成目標日・グラフ期間の設定（1件のみ） | `id` |

IndexedDBは、アプリを開いたブラウザー／ホーム画面アプリごとの保存領域です。Safariの履歴・Webサイトデータの削除や端末の故障で失われる可能性があるため、定期的にJSONバックアップを「ファイル」などに保存してください。端末内の保存だけを唯一のコピーにしないでください。

### 食品マスターと食事記録の関係

食事記録は、記録元の食品のID（`foodId`）と一緒に、食品名・単位・栄養値も記録自体に保存しています。食品マスターを操作したときの動作は次のとおりです。

- **食品を編集した場合**：その食品から記録した**すべての日付の食事記録**に変更が反映されます。食品名・種類・単位・栄養値が更新され、各記録の数量はそのままで栄養値が再計算されます。「ほかの日の食事をコピー」で作った記録も対象です。
- **食品を削除した場合**：その食品に紐づく食事記録も**一緒に削除されます**。削除前に、対象の記録件数を示した確認が表示されます。
- **手入力の記録**（「手入力で追加」で作った記録）：食品マスターと紐づいていないため、食品マスターの編集・削除の影響を受けません。
- **ほかの日の食事をコピー**：コピー元の記録をそのまま複製します。複製した記録もコピー元と同じ食品に紐づくため、上記の編集・削除の対象になります。

### バックアップと復元

- JSONバックアップには食品・食事・体重・設定がすべて含まれます。
- 復元前にファイル全体を検査します。形式エラーがあれば既存データは一切変更しません。
- 復元すると、現在の全データがバックアップの内容に置き換わります（実行前に確認が表示されます）。

### オフライン動作

Service Workerが `index.html`、CSS、JavaScript、マニフェスト、アイコン、成分表のデータ（`seibun.json`）をキャッシュし、初回読み込み後は主要機能をオフラインで利用できます。アプリは常にキャッシュから表示します。

新しい版への更新は、`sw.js` のキャッシュ番号が変わったときだけ行われます。オンラインでアプリを開いたときに新しい番号を検出すると、全ファイルをまとめて取得し、すべてそろった場合だけ新しい版に切り替えます（次にアプリを開いたときから反映）。取得が途中で中断した場合は、古い版がそのまま使われます。ファイルが1つずつ入れ替わって新旧が混ざり、起動できなくなることを防ぐためです。

## 起動方法

### PCで動作確認する

Service Workerを有効にするため、HTTPSで配信します（初回の証明書準備は次の「iPhoneへの導入」の手順1を参照）。

```powershell
python start_server.py --cert cert.pem --key key.pem
```

表示された `https://PCのIP:8443/` をブラウザーで開きます。`start_server.py` は、決められたアプリのファイルだけを配信します。

#### 証明書と PC の IP アドレス

- 開発用サーバーの証明書（`cert.pem`）は、作ったときの **PC の IP アドレス** 用です。IP アドレスが変わると iPhone から正しく接続できなくなるので、ルーターの DHCP 固定割当（IP アドレスの予約）で、この PC にいつも同じ IP アドレスが割り当てられるようにしておくと便利です。
- iPhone の Safari で「安全ではありません」と出たり、ホーム画面のアイコンが付かなかったりしたら、まず `ipconfig` で PC の IP アドレスが変わっていないか確かめます。変わっていたら、次のコマンドで証明書を作り直し、`start_server.py` を起動し直します。

  ```powershell
  .\mkcert.exe -cert-file cert.pem -key-file key.pem <今のIPアドレス>
  ```

- `mkcert.exe` は Git に入れていません。公式の GitHub のリリースページ（https://github.com/FiloSottile/mkcert/releases ）から Windows 用（`mkcert-vX.X.X-windows-amd64.exe`）をダウンロードし、名前を `mkcert.exe` に変えてこのフォルダー（`start_server.py` と同じ場所）に置きます。初めて使うときは `.\mkcert.exe -install` を実行します。
- `cert.pem`・`key.pem` も Git に入れていません（`.gitignore`）。それぞれの PC で上のコマンドで作ります。`key.pem` は公開・共有しないでください。
- `start_server.py` は配信するファイルの一覧（`APP_FILES`）を起動時に読むので、ファイルを追加したら起動し直します。

### Windows PCからiPhoneへ非公開で導入する

この方法ではアプリをインターネットに公開せず、自宅などの同じWi-Fi内で最初のインストールをします。初回のセットアップ時だけiPhoneからPCに接続できる必要があります。アプリをホーム画面に追加し、一度開いて読み込みが完了すれば、PCを止めてもオフラインで使えます。

#### 1. PCでローカル証明書を用意

1. Python 3をPCに用意します（このアプリの配信に必要。無料）。
2. [mkcert](https://github.com/FiloSottile/mkcert/releases) の Windows 用を入手し、`mkcert.exe` としてこのフォルダーに置きます（無料の証明書作成ツール。初回ダウンロードにインターネット接続が必要です）。PowerShellで `.\mkcert.exe -install` を実行します。
3. PCとiPhoneを同じWi-Fiに接続します。家庭内ネットワークを使い、ゲストWi-Fiやクライアント間通信を遮断したWi-Fiは避けてください。
4. PCのプライベートIPv4アドレスを確認します（`ipconfig`）。例では `192.168.1.25` とします。
5. このフォルダーで次を実行します。IPは実際の値に置き換えてください。

   ```powershell
   .\mkcert.exe -cert-file cert.pem -key-file key.pem 192.168.1.25
   .\mkcert.exe -CAROOT
   ```

   `.\mkcert.exe -CAROOT` が表示するフォルダーに `rootCA.pem` があります。`rootCA-key.pem` は秘密鍵です。**iPhoneに転送したり、公開したりしないでください。**

#### 2. iPhoneでPCの証明書を信頼

1. PCで次を実行します（CAフォルダーのパスは実際の結果に置き換えます）。

   ```powershell
   python start_server.py --cert cert.pem --key key.pem --root-ca "C:\Users\あなた\AppData\Local\mkcert\rootCA.pem"
   ```

   表示されるHTTPSアドレスと証明書配布用HTTPアドレスを控えます。Windows Defenderファイアウォールが許可を尋ねたら、**プライベートネットワークだけ**許可します。公開ネットワークでは許可しないでください。
2. iPhoneのSafariで `http://PCのIP:8000/rootCA.pem` を開き、証明書をダウンロードします。iOSの案内に従い設定プロファイルをインストールします。
3. iPhoneの「設定」→「一般」→「情報」→「証明書信頼設定」で、このローカル証明書を完全に信頼します。iOSの表示はバージョンにより多少異なります。
4. Safariで `https://PCのIP:8443/` を開き、証明書エラーがなく、アプリが表示されることを確認します。

この手順ではCAの公開証明書だけを同じWi-Fi経由でiPhoneに配ります。ローカルCAの信頼が不要になったら、iPhoneの「証明書信頼設定」から無効化し、プロファイルを削除してください。

#### 3. ホーム画面へ追加しオフライン確認

1. Safariの共有ボタン →「ホーム画面に追加」を選びます。
2. 追加したアイコンを開き、アプリの画面が完全に読み込まれたことを確認します。
3. Safariでアプリを一度再読み込みしてService Workerの更新完了を待ちます。食品を1件登録してからJSONバックアップを作成し、PCのサーバーを停止してiPhoneを機内モードにします。ホーム画面のアプリを再度起動し、画面と記録が残っていることを確認してください。
4. サーバーを止めた後も、食事・食品・体重・バックアップの機能は端末内で動作します。新しいiPhoneに移す場合はJSONバックアップを復元してください。

Service Workerの更新を反映するには、PCのサーバーを停止する前にオンライン状態でSafariまたはホーム画面アプリを一度開いてください。アプリを追加しただけで一度も正常に読み込んでいない場合や、SafariのWebサイトデータを削除した場合は、オフライン起動に必要なキャッシュがないため、再度オンラインで読み込む必要があります。

### macOSから導入する場合

同じPWAをMac上でHTTPS配信し、iPhoneでSafariから開いてホーム画面に追加できます。macOSでもmkcertを使う方法があり、インストールにはHomebrew等が使えます。

## アプリを変更したときの手順

1. ルート直下の `index.html` / `app.js` / `styles.css` などを編集します。
2. **`sw.js` の `CACHE` の番号を1つ上げます**（例：`genryo-note-v55` → `genryo-note-v56`）。上げないと、iPhone側は古い版のまま一切更新されません。番号は過去に使った値より必ず大きくしてください。
3. 新しいファイルを追加した場合は、`sw.js` の `APP_FILES` と `start_server.py` の `APP_FILES` の両方に追加し、`start_server.py` を起動し直します。
4. iOSネイティブ版（Capacitor）にも反映する場合は、ルートの10ファイル（`index.html`、`app.js`、`styles.css`、`sw.js`、`manifest.webmanifest`、`icon.svg`、`apple-touch-icon.png`、`icon-192.png`、`icon-512.png`、`seibun.json`）を `www/` にコピーしてから、次を実行します。`ios/App/App/public/` へのコピーと、iOSプロジェクトの設定の更新が行われます。

   ```powershell
   npx cap sync ios
   ```

保存データの形式（IndexedDBの構成やバックアップ形式）は、既存データとの互換性に関わります。変更する場合は、`app.js` の `DB_VERSION` や `BACKUP_VERSION`、復元時の検査処理もあわせて見直してください。

## iOSネイティブ版（Capacitor）について

`ios/` にCapacitorのiOSプロジェクトがあります（アプリID `jp.example.genryosupport`、アプリ名「カテログ」。ホーム画面に出る名前は `ios/App/App/Info.plist` の `CFBundleDisplayName`）。アプリのアイコンは `ios/App/App/Assets.xcassets/AppIcon.appiconset/AppIcon-512@2x.png`（1024px、`icon.svg` から書き出したもの）です。ネイティブアプリとしてビルド・署名・配布するにはMacとXcodeが必要で、Windowsでは `npx cap sync ios` によるファイル同期までしかできません。ネイティブ版のビルドと実機動作は未確認です。PWAとしての導入には、MacやApple Developer Programの有料登録は不要です。

## 制約・費用

- iPhone（Safari でホーム画面に追加した PWA）で日常的に使い、表示とオフライン動作を確認しています。
- PC側にPython 3（無料）とmkcert（無料）が必要です。mkcertの初回入手にはインターネット接続が必要です。iPhoneのインターネット公開、サーバー契約、オンラインデータベース、有料サービスは不要です。
- iPhoneに最初から完全オフラインでインストールすることは、このローカルPWA方式だけではできません。初回に同じWi-Fiからアプリを読み込む必要があります。iOSの「ファイル」からHTMLを開くだけでは、PWAのインストールとオフラインキャッシュを確実に構成できません。
- iOSのストレージは端末・OSの管理下にあります。大切な記録は、JSONバックアップを別の安全な場所にも保管してください。
